## 审查结论与修正

方向可行，原讨论稿尚不足以直接作为验收标准，补充以下约定：

- 旧牌谱不完整保存再加注权与公开行为历史。新行动帧保存行动前、带版本的可见状态；缺少可靠上下文的旧记录显示无法分析，不拿后来揭晓的牌评价当时决策。
- 现有 `tie_rate` 是平分权益份额，继续保留兼容性。界面显示的平局事件概率另设 `tie_probability`，胜率、平局概率与权益分别标注。
- B 采用有限候选行动、共享范围样本和有预算的后续行动模拟。到深度上限使用明确说明的摊牌估值；这不构成完整最优策略或 GTO。隐藏信息不能进入模拟行动者的策略输入。[信息集搜索研究](https://eprints.whiterose.ac.uk/id/eprint/75048/1/CowlingPowleyWhitehouse2012.pdf)指出了直接明牌化搜索的策略融合问题。
- 比较候选行动时使用相同样本；实际下注尺寸必须参与比较。采样差异不足以区分时标注接近，取消或零有效样本不提供数值结论。
- 新画像以独立、可合并的逐手计数持久化，保留在累计账目中。删除回放、保存重试和重新启动不能改变已累计结果。

## 计算与界面边界

1. `CoachContext` 负责可见状态及版本验证；只保留行动者底牌、当时公共牌与公开行动。真实牌堆、其他人的底牌、私有性格和结果不进入决策评估。
2. `CoachAnalysis.live` 使用中立范围设置计算胜率、平局概率、权益、跟注成本、底池价格和样本量。显示辅助结果时才标记该手使用了辅助。
3. `FiniteSearch` 通过 `PokerRound.apply_action()` 推进模拟行动，通过原有牌力与底池规则结算。所有采样使用独立随机源，候选行动共享抽样世界；模拟策略只能访问各行动者当时的可见状态。
4. `CoachAnalysis.review` 比较实际行动和候选行动，提供 BB 收益及采样误差。文字解释基于这些事实，不能把后来的输赢当成决策正误。
5. 地狱难度调用 B，性格只影响候选行动取舍。简单、普通、困难保留原有策略。对战与耗时基准只提供测量证据，不预设地狱必然更强。
6. 计算在后台进行，关闭、换手、重新开局和页面跳转会使旧请求失效。UI、存档写入与真实行动应用由主线程负责。退出时保留正常存档重试语义。

## 六维口径（分析版本 1）

画像描述打法及限定阶段的牌运，面积不是能力分；每个维度展示自己的分母。筛选模式、辅助状态、人数、难度、筹码深度和时间后，基础统计与画像使用相同样本。

| 维度 | 计算口径 | 绘图门槛 |
|---|---|---|
| 进攻 | 增加桌面下注价格的主动动作 / 自愿行动机会；全下跟注归跟注 | 30 次行动机会 |
| 防守 | 跟注或加注 / 面对付费决定的机会 | 30 次付费决定 |
| 入池 | 翻前有自愿付费 / 有翻前行动机会的手数；排除强制盲注 | 20 手 |
| 冒险 | 已分析决定中，追加投入占当时剩余筹码比例乘以 `1 - 权益` 的平均值 | 30 次有权益估计的决定 |
| 施压 | 低权益时增加下注价格 / 低权益行动机会；低权益阈值为 `min(0.4, 1 / 在局人数)` | 30 次低权益机会 |
| 运气 | 全下锁定后实际派奖与期望派奖之差，按 BB 累计；另给可比的标准化位置 | 5 个有结果方差的合格全下样本 |

进攻、防守、入池和施压展示原始比例，冒险展示平均风险暴露，不把它们包装为技术评分。门槛是首版的展示约定，以固定随机种子的比例区间模拟检查稳定性；不是“达到这些手数就能证明真实水平”的结论。明细保留翻前/翻后、位置、付费机会与底池价格，低权益投入不自动算错误。没有样本或未达到门槛时保留原始计数并标明样本不足，雷达轴不以零补齐；只有全部轴有效才闭合填充。

运气只统计尚有公共牌未发、至少两名争夺者、投注已全部锁定且之后没有自主行动的完整摊牌。使用必要的摊牌底牌和锁定时公共牌，重新抽样剩余发牌；不读取已弃牌的私有底牌。边池资格、退款和奇数筹码采用既有规则。归一化位置为 `clamp(0.5 + z / 6, 0, 1)`，其中 `z = 累计派奖偏差 / sqrt(累计派奖方差)`，中心表示期望值；同时必须显示 BB 偏差及有效样本数。零方差、河牌后才锁定、底牌/底池资料不完整等情况不给该轴评分。这不是整场运气，也不是盈利评分。

## DeepSeek 边界

2026-09-18 按用户确认调整为开发者提供共享 AI 服务，先在本机运行。开发者将自己的密钥填入项目根目录私有 `.env.local`，由 `tools/coach_service.py` 读取；玩家界面没有密钥输入、设置入口或额外的文字生成按钮。Godot 客户端只包含 `coach/service_url`，密钥不进入存档、Git、桌面包或 Web 资源。

打开回放即自动计算行动前局面的本地估值，再把最多 12 个可用决定的数值摘要交给本机服务。服务调用固定的 `https://api.deepseek.com/chat/completions`，使用[官方模型接口](https://api-docs.deepseek.com/)的 `deepseek-flash`、[非思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)及 JSON 输出。摘要不含完整牌谱、玩家名称、对手底牌或未来公共牌；实时数字及对手行动仍全部本地计算。

服务严格限制输入字段、请求大小、上游并发、输出 tokens 和请求次数，禁用重定向及自动重试。服务端及客户端均校验决定引用、动作与采样分类，拒绝含数字、未支持的显式动作名、保赢或确定性错误结论的生成文本；这些保守检查不能证明任意自然语言完全准确。界面标明文字为 AI 练习建议，不取代本地估值。

切换动作和全知视角继续等待同一结果；重复打开通过数值与文字缓存复用结果。离开回放或退出使客户端旧回调失效，已经开始的服务端请求可能继续完成并缓存。缺少密钥、网络异常、限额或校验失败时保留本地分析。配置、限额及缓存细节见[运行手册](../runbook.md#本机文字复盘服务)。生产部署后再替换公开服务 URL，本阶段不宣称公网可用。

## 验收

- 固定可见输入与种子，修改真实暗牌、未来发牌、对手性格和难度不改变中立分析。
- 新牌谱 JSON 往返恢复保留欠额全下后的再加注权；非法、旧版和缺字段上下文安全降级。
- 已知概率、平局、多人数边池、退款、实际非预设下注尺寸、采样不足和取消都有确定性测试。
- 实时/回放生命周期检查包括失败重试、关闭、过期结果丢弃、辅助记账和全知回放不影响建议。
- 画像检查强制盲注、全下跟注、不同分母、统计筛选、旧数据、幂等保存及删除回放后累计保留。
- 桌面与 Web 检查实际计算耗时及界面响应；固定牌序、座位轮换的对战仅用作强度诊断。
- 1280×720 和 1600×1000 检查六维图、空样本状态、实时数字和复盘内容；中英文均覆盖。

默认预算：实时显示 96 个样本；回放每个决定最多 32 个共同世界、12 步、1000 ms；地狱为 16 个世界、8 步、600 ms；画像每个决定 64 个样本、整手权益计算最多约 6 秒，存档先持久化基本牌谱，后台完成后更新累计账目。工作按批次检查取消/期限，预算不构成不同设备上的硬实时保证。运气在只剩河牌时完整枚举；更多待发牌时默认 128 次抽样、接口上限 512 次，抽样不能证明方差时不给标准化位置。
