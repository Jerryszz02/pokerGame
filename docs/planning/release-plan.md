# 稳定公开桌面首发计划与验收标准

## 目的、来源与状态

来源：用户于 2026-09-06 要求“做到稳定公开桌面首发，先把验收标准写清楚再开始做”。本文件是首发完成定义；实现与验证记录不能反过来缩减它。2026-09-07 用户明确要求零成本首发，并将真人试玩移出本 Goal；R8 因用户变更范围而取消，不记为测试通过。状态：实施与候选构建验收中；公开发布门尚未通过。

产品保持 Godot 4 + GDScript、中文、本地单人、1–5 个 AI、三档难度、无真钱、无联网、无账号、无遥测、无第三方插件。首发定位为离线休闲德州扑克；不宣称专业训练器或接近最优策略。

平台与渠道仍待用户确定：在零成本约束下，建议 Windows x64 先通过 GitHub Releases 公开下载，可配 itch.io 玩家展示页；macOS 是否纳入首发及其签名路径待选择，不自动缩减已准备的平台范围。Steam、iOS、Linux 不作为默认首发目标。平台确定后在本文件固定操作系统与硬件矩阵；不能把“导出了文件”当作目标平台验证。

## 实施顺序

1. 固定范围并提交本验收基线；补充失败回归，再修规则与比赛结束状态。
2. 隔离 AI 计算与主线程，处理取消/暂停/重开生命周期，增加真实调度验证与节奏设置。
3. 完善帮助、退出语义、错误提示、字体与设置，补齐 UI 与数据回归。
4. 建立可重复构建/CI/归属文件，生成候选发行包，执行压力、响应和图形验证。
5. 在目标系统验证候选包，修复技术验收发现的问题；保留验证所用提交与包哈希。
6. 逐门审计，处理 PR 检查/必要审查，合并、打版本、公开发布并重新下载验收。

规则、AI、UI 分层不变；线程只处理独立数据快照，所有最终行动仍通过规则入口。保留原工作区与用户存档；测试使用独立数据路径。变更在从最新 `origin/main` 建立的 `agent/desktop-release` worktree 进行。

## 证据记录与发布维护

当前事实以代码、实际命令结果、CI、目标系统发行包和公开下载为准。单次验收报告放入 `docs/releases/`，注明日期、提交、包哈希、环境、每个门的通过/失败/待验证状态和未解决事项；此目录在产生实际报告时创建。不得提前填写通过。

发现发布阻塞时停止公开新版本；已发版本保留历史，不覆写同版本文件。修复采用新的补丁版本，经相同相关门验证；必要时把 Release 标记为预发布并在说明中指出问题，恢复最近已验证版本的下载指引。保留玩家本地资料，不用删除资料作为常规恢复步骤。
