# 免费德扑练习游戏：非 AI 算法功能规划

状态：`计划中`。需求归档日期：2026-09-10。代码基线：`origin/main` 的 `7d27d18`。本次只编写规划，不实现功能，不代表下列能力已经验证或发布。

来源：用户在本轮讨论中确定“专业、免费的德扑练习游戏”定位，并要求先归档与 AI 算法无关的模式、配置、教学等需求。本文区分用户已确定的需求、建议方案和待确认细节；未定事项不默认视为已批准。

本文是本轮产品升级的需求入口，覆盖旧 [PRD](prd.md) 中关于成就、逐手历史、本地玩家资料的原型期非目标；旧版其他规则约束继续适用。实现现状看 [架构](../architecture.md)，运行与验证命令看 [Runbook](../runbook.md)，文档分工见 [规划索引](README.md)。

## 1. 定位与范围

### 已确定的产品原则

- 免费、单机、离线，让零基础玩家能入门，让有经验的玩家能按目标练习。
- 不售卖筹码，不设付费补充次数，不因筹码耗尽要求充值；玩家可以免费重新开桌。
- 首页面向玩家提供“新手教程”“自由对战”“练习对局”三个主要入口。“练习对局”为暂定名称。
- 分析教练采用完全本地方案，不接入联网大模型或外部分析服务。
- 继续使用 Godot 4 + GDScript；保持规则、AI、UI 分层。

### 本文范围

首页与导航、开桌配置、教程课程与交互、规则/牌型速览、练习模式的交互流程、牌谱与回放、基础统计、成就、玩家画像展示边界、本地数据保存与验收。

### 留待下一轮算法讨论

- 三档 AI 难度如何产生可验证的能力差异。
- 性格/打法的分类、参数、命名及普通/困难档中的具体行为。
- 实时分析、复盘建议的概率模型、策略依据、解释内容和计算预算。
- 画像维度、归一化、样本阈值，以及运气或能力评分的计算方法。

本文仅保留这些能力的产品入口和依赖关系，不指定参数、不承诺 GTO 或“最佳行动”准确性，也不把现有 AI 的行动标签直接当作教练结论。

非目标：联网对战、账号、云同步、在线排行榜、付费系统、新平台适配和宣传推广。进行中的自由对战断点续玩、补筹码/再买入、自动升盲均未纳入已确定范围；牌谱回放不等于续玩存档。

## 3. 首页与通用导航

| 入口 | 流程 | 完成或退出 |
| --- | --- | --- |
| 新手教程 | 课程选择 → 预设局面 → 分步操作 → 本课总结 | 下一课、重练、回首页 |
| 自由对战 | 配置牌桌 → 对局 → 单手结算 → 下一手或整场结束 | 回放本手、查看整场结果、重开、回首页 |
| 练习对局 | 配置牌桌 → 对局与可选提示 → 单手结束 → 可选暂停复盘 | 继续下一手、进入回放、回首页 |

建议将“牌局记录”“我的统计与成就”“设置”作为次级入口，不与三个开始入口争抢层级；最终布局在 UI 实施时确认。所有入口保持中文，延续现有像素风与可读性标准。

- 页面返回须保留尚未提交的开桌选项，不意外开始新局。
- 离开未完成对局时沿用明确确认；提示哪些内容已保存、哪些会放弃。
- 空记录、无教程进度、统计不足、保存失败都必须有明确状态，不展示伪造示例战绩。
- 设置、速览、暂停和复盘覆盖层阻止牌局自动推进；关闭后只恢复仍有效的当前牌局。

## 4. 自由对战与练习对局配置

### 已确定项

| 字段 | 要求 |
| --- | --- |
| 难度 | 保留简单、普通、困难三档；显示名称统一，内部既有标识可保持兼容 |
| 对手数量 | 1～5 名 AI |
| 初始筹码 | 至少支持每人 1000、2000、5000、10000 |
| 大小盲 | 开桌时可选，不再只允许固定 10/20 |
| 性格入口 | 普通、困难档支持预设选项；选项内容和行为依赖后续算法方案 |

### 建议的第一版交互

- 所有人使用相同初始筹码；额外的座位独立筹码设置暂不引入。
- 大小盲先提供 `5/10、10/20、25/50、50/100` 四组预设，默认保留 `10/20`；具体预设待确认。
- 显示筹码与大盲倍数，例如 `2000 筹码 · 10/20 盲注 · 100 BB`，并解释 BB 是大盲单位。
- 一场内盲注保持固定；不把“起手可选”扩展成自动升盲。
- 性格选择可以统一设置或逐座位设置；逐座位能力为建议方案，尚未确定。最终选项未定前不发布无效控件。
- 练习模式复用自由对战的基础配置，再增加提示可见性与逐手暂停选项。

### 校验与生命周期

- 筹码和盲注使用合法正整数，校验小盲小于大盲、组合在支持范围内；无效旧设置回退安全默认值并提示。
- 配置在开桌时形成快照；修改下一桌的偏好不能改变正在进行的牌局。
- 显示、筹码支付、最小加注、全下、边池和整场总结使用同一份实际配置。
- 现有 AI 含按固定筹码值计算的判断；扩展筹码/盲注对 UI 与规则可独立实现，但完整发布须等待算法讨论确认不同筹码尺度下的行为。不得把“配置生效”当成“AI 已适配”。

## 5. 零基础教程

已确定：发牌、局面、对手行动和教学顺序由开发者预设，用户通过实际操作完成课程。不能只用长说明弹窗替代教学。

以下为建议课程编排，最终文案与课数在实现前细化：

| 课程 | 玩家应学会 | 验收动作 |
| --- | --- | --- |
| T1 认识牌桌 | 底牌、公共牌、筹码、底池；从可用牌中选最佳五张 | 指认区域并完成一次五张牌组合 |
| T2 牌型大小 | 九类牌型顺序、同牌型比较、平局 | 在预设例子中比较大小并查看解释 |
| T3 轮到我怎么办 | 让牌、跟注、弃牌、加注到、全下 | 在合法局面中逐项操作；解释加注到与追加金额的区别 |
| T4 完整打一手 | 翻前、翻牌、转牌、河牌、摊牌的顺序 | 在引导下从发牌走到结算 |
| T5 庄位与盲注 | 庄位轮换、大小盲、行动顺序及单挑差异 | 根据预设牌桌识别下一位行动者 |
| T6 结算进阶 | 全下、主池/边池、平分、未跟注筹码返还 | 阅读结算分解，理解返还金额与净盈利的区别 |
| T7 入门自测 | 综合使用基础规则 | 完成减少提示的教学牌局，再进入自由或练习模式 |

- 每步只介绍当前需要的知识，提供突出标记、操作提示、即时解释和重复尝试。
- 教学场景可从指定检查点重置；关卡和教程脚本有版本标识，进度按已完成课程保存。
- 教程控制器只负责准备合法局面、提示和安排合法动作。用户与预设对手行动仍经 `PokerRound.apply_action()`；牌型比较仍经 `HandEvaluator.evaluate()`。不为讲解绕过规则或伪造胜负。
- 预设分支必须闭合：允许用户选择的其他动作也有明确后续；若当前步骤仅练一种操作，解释限制原因并允许退出。
- 已完成课程可重练；重练不重复累计普通战绩或稀有牌型成就。
- 教程记录可以供课程内查看，必须带教程来源，不混入自由对战统计。

## 6. 规则速览与牌型速览

- 两个入口均放入设置；建议在牌桌暂停/帮助区域提供快捷入口。
- 规则速览：整场目标、单手流程、行动定义、庄位/盲注、全下/边池/分池、退出与保存语义。
- 牌型速览：从高到低展示九类牌型、五张示例牌和简短说明；解释 A 可作顺子低牌、同类牌型比较及公共牌平局。
- 示例必须按现有评估器验证；如单列皇家同花顺，明确它属于同花顺，不另造牌型等级。
- 速览可滚动、可关闭，不遮挡关闭入口；打开期间冻结游戏，关闭后恢复原状态。

## 7. 练习模式的交互边界

已确定：玩家可选择是否查看实时分析，也可在一手结束后暂停进行复盘；自由对战也有回放与复盘入口。教练完全本地运行。

本轮只规划：

- 提示显示/隐藏、逐手暂停的开关与状态保存。
- 结算后“复盘本手 / 下一手”的流程；回看期间不自动发下一手。
- 分析中的加载、不可用、失败与重试状态。没有分析结果时不显示虚假建议；结果未就绪不阻止玩家关闭面板或返回。
- 分析展示只读独立牌局信息；旧手牌的迟到结果不能出现在新手牌里。
- 隐藏提示不改变发牌、对手行为或随机序列。
- 记录每手是否实际查看过实时辅助，供后续统计筛选；事后复盘与对局中使用提示分别记录。

具体建议文本、行动评分、胜率估计和推理机制不在本轮定义。阶段开发可验证界面状态，但算法接入验收前不能把该模式标记为完整可用。

## 8. 牌谱保存与回放

### 功能范围

- 自由对战和练习对局按手保存记录，按整场分组；一手结束即可查看，不必等整场结束。
- 列表显示时间、模式、人数、难度、筹码/盲注、本手净变化；支持选择一手进入回放。
- 支持上一动作、下一动作、自动播放、暂停，以及跳转到翻前/翻牌/转牌/河牌/摊牌等实际发生的阶段。
- 对已结束手牌可切换玩家当时视角与全知视角；全知视角能查看包括已弃牌玩家在内的全部已发底牌。
- 实时自由对战不提供看对手底牌的入口。回放中尚未发出的公共牌不提前出现在当时视角；无人争夺而提前结束的手牌不伪造后续公共牌。
- 预留回放分析入口；评价历史决策时只能使用当时可知信息。显示真实底牌与评价决策所使用的信息要分离。
- 查看、快进、重复播放和打开分析都不重新计入统计或成就。

### 必需记录内容

建议至少保存：格式版本、唯一整场/手牌标识、模式及辅助使用标记、开桌配置、座位/庄位/盲位、手牌开始筹码、已发底牌、公共牌、结构化行动顺序、每阶段必要状态、投入/返还、主池/边池、分池结果和逐人净变化。

实现时选择“初始状态 + 结构化事件”或带检查点的重建方式；不把人类可读文字日志或单独随机种子当作完整牌谱。回放使用独立只读状态，不能复用正在打牌的权威对象。

## 9. 基础统计、画像与成就

### 不依赖策略评分的统计

| 类别 | 计划统计 | 必须说明的口径 |
| --- | --- | --- |
| 手数/场数 | 完成手数、完整结束场数、赢手/平手/输手、整场胜负 | 区分手与场；提前离桌单列，不擅自判整场输赢 |
| 筹码 | 净盈利、最大单手净盈利、单场最高筹码及相对入场倍数 | 底池返还不等于净盈利；各盲注档分组或明确换算，不能只合并原始筹码比较能力 |
| 胜出方式 | 摊牌获胜、无人争夺获胜、分池 | 赢得某个边池与整手净盈利分别记录；类别可以重叠，不强行相加等于总手数 |
| 牌型 | 摊牌时的最佳牌型次数、以该牌型获奖次数 | 统一用七选五评估结果；未到摊牌或缺少公共牌不推测最终牌型；平分与独赢可区分 |
| 分类筛选 | 模式、是否查看实时辅助、难度、人数、筹码深度 | 教程单列；带辅助与独立对局不混成统一成绩 |

“赢手”与“净盈利手”分别命名：前者表示获得主池或边池的独占奖励，平分单独标记；净盈利按收回减投入计算。详细边池分类在实现测试用例中固化，避免多计或用模糊的“胜率”代表所有指标。

### 玩家画像

已确定产品意向：用六边形或八边形图帮助玩家理解自己的打法。现阶段只保留展示区、时间/模式筛选、样本量、不足数据状态和指标说明入口；图形边数、维度、算法与阈值全部待讨论。

不得用随意拼出的百分比填满雷达图；不默认面积越大水平越高，不用短期赢率证明能力。“运气”等需要估算的指标不属于本轮基础统计实现门槛。

### 成就分类与触发

| 类型 | 示例（名称与阈值待定） | 约束 |
| --- | --- | --- |
| 教学 | 完成第一课、完成入门课程 | 只累计教程进度，重复通关幂等 |
| 练习过程 | 第一次完整复盘、完成不同人数或筹码深度的练习 | 根据实际发生事件触发，不因打开空页面触发 |
| 牌型里程碑 | 葫芦、四条、同花顺出现若干次 | 以正常完成的摊牌为口径，区分“形成牌型”和“以牌型获胜”；预设教程和重复回放不计入 |
| 战绩里程碑 | 单场筹码达到入场时的 2 倍、3 倍等 | 明确“当前/最高筹码 ÷ 初始筹码”与“净赚倍数”的区别；奖励门槛在所选人数下可达 |

同额入场且无补筹码时，总筹码守恒；最多六人意味着最终筹码最多为入场的六倍，净赚最多五倍。不要生成该模式无法达到的成就。

成就不锁基础教学或练习权限，不发放需要充值补充的入场资源。成就是否计入带辅助练习、是否奖励装饰品，留待确认；统计必须先保留来源以支持该选择。

## 10. 本地数据与兼容

- 逻辑上区分设置、教程进度、牌谱、聚合统计、成就。具体文件格式/目录在实现时确定，不能把全部长历史无界塞进现有 profile。
- 为新数据增加格式版本、手牌唯一标识和幂等提交机制；退出、重复打开、重试保存不得重复记战绩或成就。
- 迁移保留原设置与旧聚合统计；旧数据缺少牌谱、模式、牌型等细项，显示为“历史汇总/无法追溯”，不伪造明细或反推成就。
- 已结束手牌可靠写入后才宣称已保存；原子写入、失败提示和可重试路径应覆盖写入中断/目录不可写等情况。
- 单条牌谱损坏不能阻止启动；隔离并提示，保留其他有效资料。未知新版本数据不得被旧格式静默覆盖。
- 教程进度保存不等于自由对战中途续局；后者仍须独立确认与设计。
- 实施牌谱持久化前须确定容量、保留/清理方式，以及删除牌谱是否影响累计统计/成就。清理和重置分别提示影响范围、明确确认，不静默丢弃记录。
- 本轮不增加遥测、账号或数据上传。自动测试使用隔离路径，不读写玩家真实存档。

## 11. 实施阶段与依赖

以下为建议执行顺序，不是本轮代码实施授权或已完成清单。

| 阶段 | 非算法交付 | 退出条件 |
| --- | --- | --- |
| P1 模式与配置 | 首页导航、自由对战配置、规则/牌型速览、配置校验和保存 | 流程闭合，配置真实作用于规则；性格入口不发布空功能；不同筹码尺度的 AI 发布验收另有依赖 |
| P2 教学 | 课程脚本、预设合法局面、步骤交互、进度与重练 | 零基础课程从进入到总结闭合；重练不污染正常统计 |
| P3 记录与回放 | 本地牌谱、整场/手牌列表、逐动作/逐阶段回放、视角切换 | 完成手牌可跨启动回放；数据与原牌局一致；不改变原状态或重复记账 |
| P4 统计与成就 | 细化统计、分组筛选、首批确定性成就与旧数据迁移 | 同一批牌谱可核对统计，成就幂等，缺失历史信息明确 |
| P5 练习与展示集成 | 提示开关、逐手复盘流程、画像页面的数据/空状态 | 流程可独立验证；完整教练和画像发布须等待算法定义与验收 |

P2 与 P3 可在职责和写入边界明确后并行。P4 依赖 P3 的稳定记录口径。当前不承诺开发时长；每阶段实施前补齐其具体待确认项与测试用例。

## 12. 验收清单

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| N1 | 从首页进入三模式、返回、取消配置 | 不误开局、不丢草稿设置；未完成模式不伪装可用 |
| N2 | 不同人数、四档筹码与支持的盲注组合 | 实际初始筹码/收盲/最小加注与配置一致；全下、边池、余数分配和资金守恒仍正确 |
| N3 | 每课正常完成、错误操作、退出、重练和重启 | 引导可理解，分支不死锁；进度保留；正常战绩/稀有牌型成就不增加 |
| N4 | 在行动/等待/结算中打开两类速览 | 内容与规则一致；暂停期间无偷偷推进；返回只恢复当前牌局 |
| N5 | 普通摊牌、弃牌结束、全下、多边池、平局回放 | 每动作/每阶段的牌面、筹码、底池与原局一致；未发生阶段不伪造；对手底牌仅在完结回放可见 |
| N6 | 反复回放、保存重试、退出重进 | 每手仅统计一次，成就仅解锁一次，真实牌局不被回放修改 |
| N7 | 教程/自由/练习混合记录与旧 profile 迁移 | 来源可筛选；旧汇总保留但不编造明细；缺失数据不显示伪零值画像 |
| N8 | 不可写目录、损坏单条记录、格式版本不兼容 | 明确提示且仍可退出；有效存档不被覆盖，其他记录仍可读取 |
| N9 | 最小支持窗口与更大窗口 | 菜单、长牌型说明、配置、回放控件无截断/越界/遮挡，数字和花色清晰 |
| N10 | 完整断网下运行非算法功能 | 无登录/充值/联网要求；输光后可免费重新开桌 |

实施阶段应先运行改动相关的规则/数据测试，再按需扩展 UI 回归；[现有测试计划](test-plan.md) 与 [UI 验收](ui-acceptance.md) 作为回归基线，不代表已经覆盖本表新能力。实际命令和引擎获取方式沿用 [Runbook](../runbook.md)。本次为文档变更，只做 Markdown 索引、链接及差异检查，不宣称游戏测试通过。
