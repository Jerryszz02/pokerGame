# PokerGame 宣传片独立审核标准

锁定日期：2026-10-15。适用于本次商店 / YouTube 横版、小红书横版、Bilibili 横版、YouTube Shorts 四条成片。依据为 `docs/promo-video-scripts.md` 的分镜、内容与连续性要求；当前版本教程以 v1.4 三手引导替换历史七课分镜。

本标准由不参与剪辑制作的独立审核 agent 制定，制作开始后不因成片表现降低门槛。审核 agent 不修改制片文件。

## 通过规则与修改上限

- 每条视频独立计分，总分 100 分；**总分至少 85 分且所有硬性门槛通过**才可标为 `Pass`。
- 首次提交为 **R0 初版审核**。不通过后，每条视频最多进行 **R1、R2、R3 三轮修改及重新审核**，不把初版计入三次修改。
- 三轮后仍不通过，应保留 `Fail` 结论、未解决问题和交付限制，不继续自动修改或降低标准。
- 证据不足的项目标记 `Unverified`，不得按已验证通过处理；硬性门槛存在 `Unverified` 时，该条视频不能标为 `Pass`。
- 审核应使用实际最终 MP4、源素材与手牌连续性 manifest、客观媒体指标、音乐 / 字体 / 音效许可和发布文案。仅有抽帧不足以确认动作连续性和声音。

## 硬性失败

出现以下任一项，总分再高也必须判为 `Fail`；缺少排除该问题所需证据时标记 `Unverified`，不能通过：

1. 解码失败或严重违反时长、分辨率、画幅等目标规格。
2. 当前版本宣传片的教程仍展示旧七课，未替换为当前三手引导。
3. 主线换手，伪造动作 / 结果，牌面、金额、结算与回放不一致，或把新桌伪装成原桌下一手。
4. 将全知视角用于尚未结束的手牌，或剪辑使观众误以为实战中能看到对手底牌。
5. 关键按钮、牌面、金额或结果不可读，或被标题 / 字幕遮挡而无法理解操作。
6. 将横版牌桌直接缩进竖版，导致核心游戏信息不可辨。
7. Bilibili 的游戏界面 / 标题语言不符合中文要求，或小红书丢失商店片中的英文标题。
8. 缺少结尾至少 4 秒稳定 CTA、入口错误，或未经核实声称入口已在频道资料中。
9. 无法证明实机素材来源，或无法证明音乐等素材的使用权及所需署名已交付。

## 审核方法与证据边界

1. 使用 FFprobe / FFmpeg 获取时长、分辨率、像素比例、帧率、编解码器、音轨采样率和完整解码结果；检查响度、true peak、黑场及静音区间，区分有意设计与异常。
2. 查看全片、每个镜头代表帧和关键动作前后逐帧；按 `960×540` 横版与 `360×640` 竖版进行缩小预览，检查标题、字幕、安全区、牌面、金额及操作可读性。
3. 将主线手牌的决策、结果、回放与完整原片及 manifest 交叉核对，不只比较宣传片内部截图。教程核对真实提示、按钮、操作与反馈；全知视角核对已结束状态。
4. 条件允许时实际听音，核对音效、音乐压低、淡入淡出、爆音及音画同步。**若工具不能实际听音，必须如实写明未听音，不能伪称已听；客观音频指标不能替代主观听音验收。**
5. 检查四条视频的语言、内容和平台特定要求；小红书与商店版交叉核对镜头 / 时长及英文标题保留情况。
6. 核对 CTA 文案、真实网址、电脑游玩提示及许可 / 发布署名文案。若未验证公网可玩，不作公网运行成功结论。

## 每轮审核输出

每条视频分别记录：

- 文件名、SHA-256、版本轮次（R0 / R1 / R2 / R3）和审核日期。
- 八项分数及总分，`Pass` / `Fail` / `Unverified` 结论，硬性门槛结果。
- 实际执行的审核方式、使用的证据、没有执行或无法执行的项目。
- 带起止时间码的可操作问题，说明观众会受到的影响。
- 最多三条优先修改建议；次要问题仍可在问题记录中保留。
- 下一轮只允许解决问题并重新验收，不改变已锁定标准；保留前轮结论供追溯。
