difficulty, live local coaching, replay decision analysis, offline written reviews,
and the six-axis player radar. It was initially delivered as an unpublished draft.

publication at 15:06 UTC (23:06 Asia/Shanghai). This documentation sync did not
publish or modify the platform post.

## Verification and limits

- The upload wrapper validated all three package manifests, archive contents,
  byte sizes, checksums and shared clean source commit before uploading.
- Butler processing completed for all channels; the public version API returned
  1.3.0 for each. A subsequent `butler push-preview --changes-only` found zero
  new, modified or deleted files against each remote build (17 Web, 9 Windows,
  and 24 macOS files unchanged).
- The public page displayed both desktop Version 1.3.0 entries and the new Web
  embed. The HTML entry returned HTTP 200 with cross-origin isolation headers.
- The exported macOS package passed its native self-test: packaged scenes,
  fonts, translations, audio and coach code, 12 configurations and one-time
  statistics. Windows native package checks and the rules/Web/worker checks
  passed in [CI run 35355457870](https://github.com/Jerryszz02/pokerGame/actions/runs/35355457870)
  and [worker run 35355457898](https://github.com/Jerryszz02/pokerGame/actions/runs/35355457898).
- Public Chrome gameplay validation was attempted, but resource downloads for
  `index.wasm` and `index.pck` ended with `net::ERR_CONNECTION_CLOSED`. A retry
  again remained on the loader. The WebAssembly URL itself returned HTTP 200
  on a separate header request. These observations do not establish a successful
  browser boot, audio, persistence or end-to-end cloud review. Full download
  validation was also interrupted by slow transfer; remote file-signature
  comparison is the completed package-integrity check.
- The existing coach service health endpoint reported ready; this checks service
  configuration, not a successful upstream review response. Local written
  reviews remain available offline.
- Windows GUI and Intel Mac gameplay were not manually revalidated. macOS is
  ad-hoc signed, not notarized. Manifests retain `public_release_ready: false`
  because the full public runtime acceptance matrix is incomplete.
